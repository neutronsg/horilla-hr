# HR 操作指南：提醒、报销报表与工资单邮件

适用于 hr.neutron.sg。日常操作使用 Yi Lei 的 HR 账号；角色和 SMTP 配置由 Admin 管理。

## 每月流程

1. 核对员工合同、薪资、入离职日期，以及员工编辑页里的 Singapore Employment / Contributions 设置。
2. 跟进主管的请假审批、审批报销，核对报销的 **Allowance on / Payroll date** 是否属于本次发薪月份。
3. 生成工资单草稿，检查基本工资、报销、扣款、CPF/员工基金、SDL 和净工资。
4. 审核完成后改为 **Confirmed**，下载工资报表供财务核对和转账。
5. 实际发薪后记录付款日期、改为 **Paid**；按公司的通知时点手动单发或批量发送工资单。
6. 检查邮件结果页；有失败时只重试失败项。

**生成工资单、改成 Paid、发送邮件，都不会自动执行银行转账。** 修改合同或员工配置也不会自动改写已生成的工资单；本次发布不包含新的薪资统一入口。

## 请假审批与知会

日常流程：**员工提交 → Reporting Manager 审批 → 员工收到结果；HR 全程收到知会。**

- 提交时，直属主管收到待审批邮件和站内通知；员工收到提交确认；员工所属公司的 **HR Manager** 角色收到 **For your information** 邮件和站内通知。
- 主管批准／拒绝，或员工发起取消时，HR 收到状态知会。HR 无需再批准一次；知会邮件不表示需要 HR 操作。
- 普通批准／拒绝只允许该申请的直属主管。HR 角色、其他人的主管、普通 Admin 权限都不能绕过这条规则。HR 同时是这位员工的直属主管时，按主管身份审批，不重复发送提交知会。
- 员工、HR 或 Admin 都不能从普通入口批准自己的申请。
- **没有主管、主管停用，或把自己设为主管**：申请保持待审批，HR 知会中提示检查 **Employee → Edit → Work Information → Reporting Manager**。保存有效主管后，待审批申请会通知新主管。系统不会自动批准。
- HR 接收人由员工所属公司的现有 HR Manager 角色及请假查看权限解析；不需要维护姓名名单或增加新权限。管理员负责角色和权限配置。

确实需要管理员代处理时，在待审批记录打开 **Admin intervention**，选择批准／拒绝并填写原因。系统记录操作者、时间、结果和原因。此入口只对该公司的 Admin（需有请假修改权限）或超级管理员开放；不是 HR 的日常审批步骤。Yi Lei 若同时拥有 Admin 角色，会看到这个独立例外入口，普通审批仍遵守主管规则。

批准只扣一次余额；重复操作、已处理页面或不属于自己的待审批记录不能再次扣余额或覆盖结果。拒绝需要填写原因。申请评论区保留决定记录。

目前使用直属主管单级审批，**不需要配置 Multiple Approval Conditions**。已有明确配置的多级审批链仍按原顺序执行，不能从普通审批入口跳过其他审批人。

邮箱优先使用工作邮箱，未填写时使用员工账号邮箱。邮件链接需要登录，邮件本身不代替审批。**Sent 仅表示 SMTP 接受**；未收到时请检查邮箱、垃圾邮件及邮件日志。

## 配置报销提醒

入口：**Settings → Payroll → Claim Reminders**。也可从 **Payroll → Encashments & Reimbursements → Claim reminders** 进入。

[直接打开报销提醒设置](https://hr.neutron.sg/payroll/claim-reminders/)

两类提醒分别启停。上线时均保持关闭，HR 确定公司的规则后再启用。

### 员工提交提醒

设置每月截止日、提前几天提醒、发送时间。界面预填值只是配置起点，尚未启用；请按公司的实际规则修改并保存。

例如：截止日 25，提前 3 天，09:00 → 每月 22 日约 09:00 发出。若截止日为 31，二月会使用二月最后一天；提前提醒可以落在前一个月。提前天数支持 0–14。

- 收件人是该公司在职、登录账号有效且有邮箱的员工。
- 已经提交一笔报销的员工仍会收到，因为他可能还有其他费用。
- 邮件说明“有费用才需要提交；没有费用无需操作”，不会认定某位员工漏交。
- 每位员工、每个截止月份只尝试一次，不会每五分钟重复发送。
- 提醒不会拒绝逾期申请，也不会替员工提交报销。

### 待审批摘要

设置每天的发送时间，并勾选启用。仅在存在 **Requested** 的费用报销时发送；无待审批申请时不发空邮件。

- 默认收件人为**该公司的 HR Manager 角色**，且本人必须拥有报销审批权限。
- 如需要，可勾选 **Also notify the Admin role**；Admin 也需具备审批权限。
- 同一人同时拥有两个角色只收到一次。不需要维护姓名名单；角色人员变动后自动按最新配置解析。
- 普通主管、其他公司的 HR，以及已停用账号不会因同名角色而收到该公司的摘要。
- 摘要包含待审批数量、总额和系统入口；审批仍在原报销页面进行。已批准/拒绝的申请不再进入下一次摘要。

当前提醒设置使用新加坡时间。调度器每五分钟检查一次，可能在设置时间后几分钟发出；当天晚启动可在当天补发，跨过日期不会补发旧提醒。取消启用并保存即可暂停。

设置页下方有最近发送结果。**Sent** 表示 SMTP 已接受邮件，不等同于员工已读或已到收件箱。**Failed** 或长时间 **Sending** 应由 Admin 检查 SMTP 和日志；为避免重复，本周期不会自动重发不确定的尝试。

## 下载报销明细与原始收据

入口：**Payroll → Encashments & Reimbursements → Claim reports & receipts**，或 Reports 里的 **Reimbursement Register**。

[直接打开报销报表](https://hr.neutron.sg/report/standard/reimbursement-register/)

1. 选择月份或自定义日期范围。
2. 选择 **Date basis**：
   - **Submitted date**：按提交时间，默认选项；结束日期包含当天全天。旧记录若没有提交时间，会保留并显示空值。
   - **Payroll date (allowance on)**：按薪资归属日期。适合查看九月工资中的报销，即使员工十月才提交。它不是费用实际发生日期。
3. 按需选择 Claim status、Claim type 和公司。历史对账如需离职员工，Employment status 请选择 **All**。
4. 点击 Apply，再在 Actions 中下载 Excel/CSV，或 **Export details + receipts ZIP**。

明细包括 claim ID、员工编号/姓名、标题、说明、金额、提交时间、薪资归属日期、状态、审批人和附件记录数。**Approved 表示已审批，不表示已经打款。** 附件记录数是存储记录数；旧数据中同一收据可能有重复记录，ZIP 会在每个 claim 内去掉相同文件内容。

ZIP 内容：

| 文件 | 用途 |
|---|---|
| `claims.xlsx` | 同一筛选范围的报销明细和汇总 |
| `receipts/claim-{ID}/` | 对应申请的原始收据，文件名不会互相覆盖 |
| `attachment-manifest.csv` | 收据与 claim 的对应关系、重复文件及缺失文件说明 |
| `README.txt` | 导出完整性说明 |

若文件名带 **PARTIAL**，表示有附件读不到；请检查清单并补齐，不能当作完整票据归档。没有附件记录会单独标注，不表示票据已审核。

页面最多展示 500 条明细，但汇总涵盖全部匹配记录；Excel/CSV 下载包含完整明细，不会静默截在 300 条。单个收据 ZIP 最多 5,000 个申请、读取文件总量最多 100 MB；超过时缩短日期范围。导出沿用公司的报表和数据导出权限，收据不会生成公共下载链接。

## 下载工资报表

[打开 Payslip Register](https://hr.neutron.sg/report/standard/payslip-register/)

优先使用现有 **Payslip Register → Actions → Export Excel**。选择薪资月份、公司和状态，核对员工、Gross Pay、Deductions、Net Pay 及汇总；审核/财务交接时通常选 Confirmed，已完成发薪的对账选 Paid。

此报表供审核、归档及财务核对，当前不新增银行上传格式。银行实际转账仍由财务在银行系统完成。

## 手动发送工资单

在工资单详情点击邮件图标，或在 Payroll → Payslips 勾选员工，使用原有 **Send via mail**。

- 只发送 **Confirmed / Paid**；Draft / Review Ongoing 会跳过，并提示先审核确认。
- 每位员工只收到自己的工资单 PDF。批量发送不会把别人的工资单一起寄给他。
- 操作后打开逐员工结果页：**Pending** 正在处理，**Sent** SMTP 已接受，**Failed** 本次失败，**Skipped** 尚未确认。
- **Retry failed only** 仅重试该批失败员工，不会再次发送成功项。其他月份/批次请回工资单列表选择。
- 有失败时先检查员工邮箱、SMTP 或 PDF 生成问题。若 Pending 超过五分钟，先检查邮件日志，避免重复发送已被 SMTP 接受的邮件。
- 发送邮件不改变工资单的付款状态或金额；重复手动发送属于重新发送，操作前请确认必要性。

## 常见情况

| 情况 | HR 应做什么 |
|---|---|
| 员工没有提交提醒 | 核对是否启用、日期/时间是否已到、是否在职及邮箱是否存在；查看最近结果 |
| HR 没收到审批摘要 | 核对是否有 Requested 费用报销、本人在该公司的 HR Manager/Admin 角色、审批权限及邮箱 |
| 外籍员工不需员工基金扣款 | 在员工 Contributions 明确选择适用情况并完成 HR 核实；无需每月重新配置 |
| SDL | 工资单按现有规则自动计算为雇主支出，不从员工净工资扣除；员工基金“不适用”不会关闭 SDL |
| 一笔报销出现两次 | 检查是否另加了同金额手工 allowance；报销已审批形成的金额不应再手工添加 |
| 工资单仍是旧薪资 | 工资单是生成时的快照；先核对合同与生效日期，再审核草稿的重新计算，不直接改已确认/已付快照 |
| 邮件显示 Sent 但没收到 | 检查垃圾邮件和公司邮箱投递情况；Sent 只证明 SMTP 接受，不证明收件人已读 |

## 邮件样式与内容

系统通知统一使用 Neutron 品牌样式：深蓝和青绿、内嵌公司标志、清晰的操作按钮，以及纯文字备用版本。工资单、请假、报销提醒、入职、帮助台、密码重置和报表邮件均使用此样式。

HR 手写或自动化邮件也会加上统一外框；原有正文、附件和收件人保持不变。密码重置和入职链接属于个人链接，请勿转发。邮件按钮打开系统后仍需按原有权限登录。

邮件使用已配置的 SMTP 发件地址；部分通知可显示操作人的名字，并使用 Reply-To 接收回复。不要将个人邮箱配置为未经 SMTP 服务验证的发件地址。

## 补录无薪假与手动扣款

正常无薪假申请按发生月份计算工资，CPF 自动使用扣减后的计薪工资。若 HR 补录漏记的无薪假，在对应月份草稿工资单添加 deduction，选择 **Reduce earned basic salary** 或 **Reduce earned gross salary**；系统重算员工及雇主 CPF，不需要手改 CPF 金额。

贷款、预支工资及普通多付薪资追回，应选择 **Other deduction** 或 **Reduce net pay only**，这些扣款不减少当前月份 CPF 工资。不能只凭扣款标题判断用途。

补录更早月份的无薪假或迟到，需要修正发生月份的工资／CPF 记录，不能用当前月份扣款替代历史 CPF 调整。已确认、已支付或已向 CPF Board 提交的月份，应先由 HR 核对并按正式调整流程处理；不要直接覆盖已结算工资单。

依据：[CPF Board：无薪假](https://www.cpf.gov.sg/service/article/are-cpf-contributions-payable-for-my-employee-who-is-on-no-pay-leave)、[CPF Board：工资扣款](https://www.cpf.gov.sg/service/article/are-cpf-contributions-payable-on-salary-deductions)、[MOM：无薪假工资计算](https://www.mom.gov.sg/faq/salary/how-to-compute-the-salary-of-an-employee-who-is-on-no-pay-leave-for-the-month)。

## 报销附件

提交费用报销时必须至少提供一份收据或证明文件；页面会显示附件缺失错误，不能保存。编辑已附证明的报销无需再次上传；没有任何附件的旧记录，编辑时需要补齐。假期兑现和积分兑现不要求报销收据。

## Probation 与年假：当前功能

目前 **Onboarding → Candidates → Probation ends** 可记录预计试用期结束日期；它没有代表 HR 已确认通过，也不会自动开放年假。自动年假按入职日期和三个月工龄计算，HR/Admin 可通过现有权限代录获批的提前年假。

公司的“通过 probation 后开放 AL”政策还需要与员工资料关联：预计结束日期、HR 确认通过及实际通过日期。开放申请资格与可用／预支余额需要分开，不能把通过 probation 等同于立即获得全年年假额度。这个联动目前尚未实现。
